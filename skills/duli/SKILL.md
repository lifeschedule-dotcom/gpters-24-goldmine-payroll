# 둘이검토 (AI 둘이 서로 검토하기)

## 쓰는 법 (한 줄)

- `/duli <프로젝트 이름> <목표 한 줄> <상대 AI·모델>` — 예: `/duli 대시보드 피드백 "예지님 댓글·MD 완성" GPT Astra`
- 말로 해도 된다: "둘이검토 돌려. 프로젝트는 ○○, 끝 기준은 ○○, 상대는 GPT."
- 이 파일 하나면 된다. **설치:** 이 파일을 Claude Code 채팅창에 끌어다 놓고 "내 스킬로 설치해 줘"라고 하면 Claude가 `me/.claude/skills/duli/SKILL.md`에 넣어 준다. 다시 열면 `/duli`가 보인다. GPT는 파일을 첨부하고 "이 파일을 읽고 반장으로 진행해", Codex는 AGENTS.md에 "둘이검토 요청이 오면 이 파일을 읽고 따른다" 한 줄.
- 끝나면 사용자가 받는 것: 바뀐 것 3줄, 토론으로 정한 것, 결과물 경로. 게시·배포만 사용자가 한다.

**이 스킬을 실행하는 AI가 반장이다.** 상대 AI(GPT/Codex 또는 Claude)는 짝꿍이다. 반장이 일을 나누고, 합치고, 토론을 끝내고, 완료를 선언한다. 게시·발송·삭제·배포는 사용자만 한다.

## 0. 공유 폴더부터

시작할 때 **먼저 한 번 묻는다.** "AI끼리 파일을 주고받을 공유 폴더가 있나요? 있으면 이름이나 경로를, 없으면 '없음'이라고 알려 주세요."

- 이름·경로를 받으면 → 그 폴더가 실제로 있는지 확인하고 그 안에서 작업한다.
- "없음"이면 → 지금 작업 폴더 안에 `live_collaboration` 폴더를 만들고 "여기에 만들었다"고 알린다. 원드라이브·구글 드라이브처럼 동기화되는 폴더 안이면 다른 컴퓨터의 AI도 같이 볼 수 있다.
- 두 AI 모두 같은 폴더를 보는지 첫 파일을 올린 뒤 확인한다.

파일 이름 규칙: **`<프로젝트> <순번> <할 일> → <받을 AI> - YYYY-MM-DD HHMM <작성 AI>.md`**
예: `대시보드 피드백 03 합친 글 검토 요청 → GPT - 2026-10-07 1330 Claude.md`
순번은 프로젝트 안에서 01부터 올라가고, 누가 쓰든 같은 번호 줄을 이어 쓴다. 상대의 파일은 절대 고치지 않고, 답은 새 파일로.

## 1. 시작 (반장)

인자(`$ARGUMENTS`)나 사용자 말에서 뽑는다. 빠진 것만 한 번 묻는다.

- 프로젝트 이름(파일 이름 앞머리)
- 목표와 **완료 기준**(무엇이 되면 끝인지, 한 줄)
- 상대 AI와 모델 지정(예: "GPT, Astra로")
- 결과물 저장 위치

협업 규칙 파일(예: `AI협업규칙.md`)이 있으면 읽는다. 기존 순번이 있으면 이어 쓴다.

## 2. 일 나누기

반장이 **01 작업 분배** 파일을 올린다. 상대가 따로 설명 없이 바로 일할 수 있게 배경·목표·현재 상태·완료 기준·결과물 저장 위치·지키는 것을 다 적는다. 자기 몫은 직접 한다. 아래 「짝꿍 프롬프트」를 01 파일 맨 아래에 붙여 상대가 규칙을 알게 한다.

나눌 때 기준: 사실 조사·대안 비교·다른 시각 검토는 상대에게, 합치기·최종 판단·기록은 반장이.

## 3. 폴더 감시 — 양쪽 모두

- **Claude:** `Monitor`로 공유 폴더에 `→ Claude` 새 파일이 생기면 알리게 한다(최대 30분, 끝나면 재무장). 폴링하지 않는다.
- **GPT:** 2분마다 폴더를 확인해 `→ GPT` 새 파일을 읽는다.
- 새 파일이 오면: 읽기 → 일하기 → 같은 규칙의 새 파일로 답하기. 답에는 **한 일 / 증거(경로·근거) / 확인 못 한 것 / 판단이 갈리는 것(있으면 선택지+추천+근거)**.
- 30분 넘게 답이 없으면 반장이 사용자에게 한 줄 알린다(동기화 지연일 수 있음).

## 4. 합치기 (반장)

분배한 일이 다 돌아오면 반장이 **최종본 하나**로 합친다. 합치기 전 원본은 `백업\`에 `… vN.md`로 둔다. 합친 글을 만들면 바로 5로 간다. 조각 상태로 끝내지 않는다.

## 5. 서로 검토 — 원칙: 합친 글 뒤 서로 최소 1번씩

1. 반장이 **스스로 검토**를 먼저 한다. 기준은 둘: 틀린 것, 실제로 안 통할 수 있는 것(오작동·못 잡는 경우). 처방마다 "이게 실패하는 상황은?"을 한 줄씩 생각하고, 답이 있으면 본문에 조건을 붙인다. 고친 목록을 표로 남긴다.
2. **합친 글 검토 요청** 파일을 올린다. 묻는 것을 번호로, 답 형식을 정해서("채택 / 더 나은 대안+근거 / 틀림+근거"). 바꿀 문장은 직접 제안하게 한다.
3. 상대가 **답장** 파일을 올린다. "더 고칠 것"이 있으면 적고, 없으면 **"더 고칠 거 없음"**이라고 명시한다.
4. 반장이 항목마다 정한다: **반영 / 반영 안 함(이유) / 토론으로**. "상대가 동의했다"는 사실 확인이 아니다. 숫자·기능·정의는 출처로 확인한다.
5. **더 고칠 것이 하나라도 있었으면 → 고치고 → 판을 올리고(v3→v4) → 다시 2로.** 순번 +1.
6. **끝 조건:** 반장의 스스로 검토와 상대의 답장이 **둘 다 "더 고칠 거 없음"**인 회차가 한 번 나오면 끝.

### 의견이 갈릴 때 — 사용자에게 묻지 말고 토론으로 끝낸다

같은 지적이 두 회차 연속 나오면(서로 생각이 다른 것) **의견 맞추기 파일**을 연다. 사용자의 판단이 아니라 두 AI의 근거로 결정한다.

- 반장이 `<프로젝트> NN 토론: <쟁점> → <상대>` 파일을 올린다. 쟁점 한 줄, 양쪽 주장, 각 주장이 **틀리는 조건**, 확인할 수 있는 출처·시험 방법.
- 상대는 같은 형식으로 답한다. 새 근거가 없으면 "새 근거 없음, 상대 안 채택"이라고 쓴다.
- 반장이 결정하고 이유를 적는다. 기준: 출처로 확인되는 쪽 → 실패 조건이 더 적은 쪽 → 사용자가 바로 쓸 수 있는 쪽. 결정 뒤에는 같은 쟁점을 다시 열지 않는다.
- 토론은 쟁점당 2왕복까지. 그래도 안 갈리면 반장이 **둘 다 적되 조건을 붙여** 최종본에 넣는다("A가 맞는 경우: … / B가 맞는 경우: …").
- 사용자에게는 결과만 알린다. 사업·취향·비용처럼 **사용자만 아는 사실**이 결정의 열쇠일 때만 질문 하나를 남기고, 그동안은 기본값을 정해 진행한다.

오타·표현 수준만 남으면 반장이 반영하고 끝 조건으로 본다.

## 6. 닫기 (반장)

1. **완료** 파일을 올린다: `<프로젝트> NN 완료 → <상대> - … <반장>.md`. 내용: 반영한 것 / 반영하지 않은 것과 이유 / 토론 결정과 이유 / 최종 결과물 전체 경로 / **"추가 검토 필요 없음, 폴더 확인을 멈춰도 됨"**.
2. 상대는 완료 파일을 읽으면 폴더 확인을 멈춘다. 반장도 Monitor를 멈춘다.
3. 작업 기록이 있는 프로젝트면 기록 파일 하나(`작업 내용 - YYYY-MM-DD HHMM 도구.md`)와 첫 장 한 줄.
4. 사용자에게: 바뀐 것 3줄 이내 + 토론으로 정한 것(있으면 한 줄씩) + 결과물 경로. 답장 내용을 다시 나열하지 않는다. 게시·배포 여부는 사용자가 정한다.

## 짝꿍 프롬프트 (01 파일 맨 아래에 붙이기)

```
이 프로젝트의 반장은 <반장 AI>이고, 너는 짝꿍야.
- 공유 폴더: <폴더 경로>. 2분마다 확인해서 너에게 온(→ <너>) 새 MD 파일을 읽고 일해 줘.
- 답은 같은 이름 규칙의 새 MD 파일로: <프로젝트> <순번> <할 일> → <받을 AI> - 날짜 시간 <너>.md
- 상대의 원본은 고치지 마. 답에는 한 일 / 증거 / 확인 못 한 것 / 판단이 갈리는 것(선택지+추천+근거)을 적어 줘.
- 합친 글 검토를 요청받으면 "틀린 것"과 "실제로 안 통할 수 있는 것"을 근거와 함께 적고, 없으면 "더 고칠 거 없음"이라고 분명히 써 줘.
- 의견이 갈리면 사용자에게 묻지 말고 의견 맞추기 파일에서 근거로 끝내. 새 근거가 없으면 "새 근거 없음"이라고 써.
- 게시·발송·삭제·배포는 하지 마. 그건 사용자가 해.
- "완료" 파일이 오면 폴더 확인을 멈춰 줘.
```

## 지키는 것

- 사실은 [확인 / 2차 / 추정 / 미확인]을 구분하고, 사용자 감정·의도를 추측해 적지 않는다.
- 비밀값·개인정보·대화 전체를 파일에 넣지 않는다.
- GPT가 반장일 때도 이 파일을 그대로 따른다. Claude 쪽 Monitor 대신 2분 확인으로 바꿔 읽으면 된다.
